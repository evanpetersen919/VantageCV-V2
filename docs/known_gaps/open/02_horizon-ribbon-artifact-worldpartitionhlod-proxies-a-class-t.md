### [RESOLVED] Horizon "ribbon" artifact -- WorldPartitionHLOD proxies, a class the terrain-hiding logic never matched
The pale, wavy strip at the far horizon (see the "Still a real artifact" note below, from the environment/ground entry) was investigated, not left unknown. It survived hiding Landscape actors, the Landscape show flag and a much denser fog, so a live `DebugListActorsWithMesh` query (new permanent debug RPC, alongside the new `DebugConsoleCommand` used to test hypotheses like `showflag.staticmeshes 0` without a rebuild) was used to inspect exactly what static mesh actors exist and their real hidden state, instead of guessing at more hooks. Two real, distinct findings, both confirmed live:

1. `showflag.staticmeshes 0` removed the ribbon entirely while the sky/clouds stayed, proving it was a specific static mesh, not terrain or atmosphere. The engine's own `/Engine/EngineSky/SM_SkySphere` (a `StaticMeshActor` with a painted mountain/cloud dome texture) exists in the template map -- but querying it directly showed `actor_hidden: true` (our own hide logic already caught it) while the ribbon was still visible, ruling it out as the cause despite looking like a strong match by name/texture alone.
2. The real cause: 64 `WorldPartitionHLOD` actors -- Epic's own auto-generated merged-mesh proxies standing in for distant/unloaded Landscape tiles -- a completely different class from `Landscape`/`LandscapeStreamingProxy` or `StaticMeshActor`, so the existing class-name check never matched them. `ProceduralScenarioLoader::HideIfTemplateTerrain` (refactored out of the duplicated inline predicate, now shared by the initial actor scan and reused where a streaming-timing fix was tried and ruled out -- see below) now also matches `ClassName.Contains("HLOD")`. Verified live: all 64 report `actor_hidden: true` after the fix, and the ribbon is gone in both a bare-ground scene and a real generated city, from multiple camera angles including ones that stress different World Partition cells.

**A real dead end, kept for the next person**: before finding the actual cause, a `FOnActorSpawned` delegate and then a `FWorldDelegates::LevelAddedToWorld` hook were added on the theory that World Partition streams the template's actors in late, after the one-time actor scan. Both were real, correctly-implemented fixes for a real potential problem (confirmed: only 46 of ~138 template actors were hidden by the initial scan alone) -- but neither changed the ribbon, because the actual culprit (`WorldPartitionHLOD`) was `is_spatially_loaded: false` (always resident, not streamed late) and was already being caught by the initial scan once its class was added to the match list. The `LevelAddedToWorld` hook is still real and still kept (it correctly catches anything that IS streamed in late), just not what fixed this specific bug.
